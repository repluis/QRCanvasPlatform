# Deployment to Render.com

This guide walks you through deploying **QRCanvasPlatform** on
[Render.com](https://render.com) using the included `render.yaml`
Blueprint.

The Blueprint spins up the entire stack in one click:

- **Web Service** — Laravel 13 / PHP 8.3 (Docker)
- **Background Worker** — `php artisan queue:work` (separate process)
- **Managed PostgreSQL** — 256 MB free tier

---

## 1. Prerequisites

- The repo is on GitHub (or GitLab / Bitbucket, Render supports both).
- You have a Render account (https://render.com → sign up free).
- You have **not** committed `.env` or any secrets — the Blueprint
  wires everything via environment variables.

---

## 2. One-click deploy

1. In Render dashboard → **New** → **Blueprint**.
2. Pick **"Connect a repository"** and authorize Render to access
   your GitHub account if you haven't yet.
3. Select the QRCanvasPlatform repo.
4. Render detects `render.yaml` in the repo root and shows a summary:

   - 1 web service (`qrcanvas-platform`)
   - 1 worker (`qrcanvas-worker`)
   - 1 database (`qrcanvas-db`)

5. Click **Apply**.
6. Render creates the resources. The first build takes 3–6 minutes
   (npm + composer install + asset build).

When it goes live, your app will be at
`https://qrcanvas-platform.onrender.com`.

> **Note:** the URL is hard-coded in `render.yaml` (`APP_URL`). If
> Render assigns a different name, edit the env var on the web service
> and redeploy.

---

## 3. What happens at build time

Render reads the `Dockerfile` at the repo root. The Dockerfile has
**three stages**:

1. **`assets`** (Node 20.19 alpine) — `npm ci && npm run build`,
   produces `public/build/`.
2. **`vendor`** (composer:2.7) — `composer install --no-dev
   --optimize-autoloader`, produces `vendor/`.
3. **Final image** (php:8.3-cli-alpine) — combines `vendor/`,
   `public/build/`, app source, and PHP extensions
   (pdo_pgsql, gd, mbstring, exif, zip, bcmath, intl, opcache).

The final image runs as the unprivileged `uid 1000` user (matches
Render's runtime) and exposes port 10000.

---

## 4. What happens at container start

`docker/entrypoint.sh` runs every time the container boots:

```bash
php artisan package:discover --ansi    # register service providers
php artisan storage:link               # public/storage → storage/app/public
php artisan config:cache              # cache config for perf
php artisan route:cache               # cache routes
php artisan view:cache                # cache Blade
php artisan migrate --force           # apply pending migrations
exec php artisan serve --host 0.0.0.0 --port $PORT
```

`php artisan serve` is fine for Render's free / starter tier. For a
production-grade setup, switch to PHP-FPM + Nginx (out of scope for
this Blueprint).

## 5. Environment variables

The Blueprint sets these automatically:

| Variable | Source | Notes |
|---|---|---|
| `APP_ENV` | hard-coded `production` | |
| `APP_DEBUG` | hard-coded `false` | **critical** for prod |
| `APP_KEY` | auto-generated by Render on first deploy | 32-char secret; never commit |
| `APP_URL` | hard-coded `https://qrcanvas-platform.onrender.com` | update if you rename |
| `DATABASE_URL` | Render injects from managed Postgres | Laravel parses this natively for pgsql |
| `SESSION_DRIVER`, `QUEUE_CONNECTION`, `CACHE_STORE` | hard-coded `database` | matches current local setup |
| `LOG_CHANNEL`/`LOG_STACK` | `stack`/`single` | logs visible in Render's dashboard |
| `FILESYSTEM_DISK` | `local` | ⚠ ephemeral — see §6 below |

To override any of these, go to the Web Service → **Environment** tab
and add a new key, then **Save** (Render triggers a redeploy).

## 6. ⚠️ Things to know

### 6.1 Storage is ephemeral

Generated QR PNGs (`storage/app/public/qr/*.png`) **disappear on every
redeploy** because Render's filesystem is ephemeral. Three options:

- **Add a Render Persistent Disk** ($1/month for 1 GB) mounted at
  `/var/www/html/storage`.
- **Switch to S3** — set `FILESYSTEM_DISK=s3` and add `AWS_*` env vars
  (already templated in `.env.example`).
- **Live with it** — QR codes are regenerated on demand when a user
  visits `/qr/love` and then cached by the CDN.

### 6.2 Queue worker is separate

`QUEUE_CONNECTION=database` means jobs (cache writes, sessions, etc.)
sit in the `jobs` table until the worker picks them up. The Blueprint
provisions `qrcanvas-worker` for this. If you see "queue not
processing" in Render logs, check that worker isn't paused.

### 6.3 APP_KEY

Render generates the key once on first deploy via `generateValue:
true`. **Do NOT** put a real `APP_KEY` in `render.yaml` or any
committed file. If you ever rotate the key, the Web Service's
Environment tab → edit `APP_KEY` → Save.

### 6.4 First deploy may need a manual push

If you see "no migration ran" after the first deploy, push a small
commit (e.g. touch `README.md`) — Render sometimes treats the very
first deploy as a build-only step and skips the entrypoint. After
that, every push will run the full entrypoint.

### 6.5 Cold start

Free / starter instances sleep after 15 min of no traffic. First
request after a sleep takes ~30 seconds. Upgrade to a higher plan
to remove this.

### 6.6 Custom domain

Render → Web Service → **Settings** → **Custom Domains** → add
`pages.yourdomain.com` and follow the DNS instructions. Then update
`APP_URL` accordingly.

## 7. Manual deploy (without the Blueprint)

If you prefer to click through the dashboard instead of using the
Blueprint:

1. **Database**: Render → New → PostgreSQL → name `qrcanvas-db` →
   create.
2. **Web Service**: New → Web Service → pick repo → **Runtime: Docker**.
   Use the included `Dockerfile` (Render detects it automatically).
   Set env vars from §5 above. Use `https://...onrender.com` as
   `APP_URL`.
3. **Worker**: New → Background Worker → pick the same repo → same
   Dockerfile → **Start Command**:
   `php artisan queue:work --tries=1 --timeout=0 --sleep=3`

The web service and worker must both have `DATABASE_URL` pointing
at the database you created in step 1.

## 8. Local sanity check before pushing

You can build the Docker image locally to catch errors before
Render does:

```bash
docker build -t qrcanvas-test .
docker run --rm -p 10000:10000 \
    -e APP_KEY="base64:$(php -r 'echo base64_encode(random_bytes(32));')" \
    -e DB_CONNECTION=sqlite \
    -e DATABASE_URL="" \
    qrcanvas-test
```

If the container starts and `/up` returns 200, you're good.

## 10. Troubleshooting

| Symptom | Likely cause | Fix |
|---|---|---|
| "Class not found" errors | composer install didn't autoload | Check build log; verify `--optimize-autoloader` |
| Frontend shows raw `@{{ }}` | `npm run build` didn't run | Check Node version; Render needs Node 20.19+ (set in `render.yaml` build env) |
| Storage 403 on `/storage/qr/...` | `storage:link` didn't run | `render exec` into the container and run `php artisan storage:link` |
| "could not find driver pgsql" | Missing PHP extension | Verify `pdo_pgsql` is in the Dockerfile (it is) |
| DB connection refused | Wrong DB host | Use `DATABASE_URL` from Render's Internal Database, not External |
| First request takes 30s | Cold start on free tier | Upgrade plan or use a cron-job ping service |
